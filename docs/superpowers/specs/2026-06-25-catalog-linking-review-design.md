**Status:** Draft
**Date:** 2026-06-25
**Author:** Archimedes AI
**Related specs:**

## Goal

Add a final review step to the Archimedes wizard that summarizes the catalog resolution outcome of a run: which fact sheets were automatically linked to the Reference Catalog, which were not but have plausible candidates worth manual review, and which legitimately have no match and were created as custom. Each row links directly to the corresponding fact sheet in LeanIX for manual action when needed.

## Non-goals

- **No in-wizard manual linking UI.** Linking HIGH/MEDIUM matches is delegated to the LeanIX native UI, which already has the catalog search built in. We provide deep links, not a reimplementation.
- **No cross-session persistence.** The report lives in the session folder; the wizard does not maintain a history of past runs.
- **No diff with previous runs.**
- **No editing of the report from the UI.**

## Why this and not Option A (wizard mapping UI)

Earlier discussion considered building an interactive mapping screen inside the wizard for HIGH/MEDIUM candidates. We rejected that approach because:

1. Reviewing 5–30 names visually is the same effort whether done in our UI or LeanIX's
2. LeanIX already has a catalog search UI with candidate previews, vendor info, and descriptions — reimplementing it adds no value
3. Users who own the workspace already know the LeanIX UI
4. A linking error is correctable inline in LeanIX

Instead, we make the post-push workflow obvious: a single screen shows everything that happened, and direct links jump users to the right place to finish the job.

## Architecture

### Flow

```
Step 7 (Push)
    │
    ├─► catalog_resolution_report.json   (already generated by resolver)
    │
    └─► push_uuid_map.json               (NEW — captured during createFactSheet)
            │
            ▼
   pipeline/catalog_report.py
            │
            ├─► catalog_report.html      (rendered for Step 8 + downloadable)
            └─► catalog_report.xlsx      (downloadable from HTML)
            ▼
   Step 8 wizard screen  (iframes HTML)
```

### Components

| Component | Responsibility |
|-----------|----------------|
| `pipeline/push_ldif.py` (modified) | Capture UUID returned by each `createFactSheet`, persist `push_uuid_map.json` |
| `pipeline/catalog_report.py` (new) | Take resolution JSON + UUID map → render `catalog_report.html` and `catalog_report.xlsx` |
| `archimedes_wizard.py` (modified) | Two new endpoints: `GET /api/session/<id>/catalog-report` (HTML), `GET /api/session/<id>/catalog-report.xlsx` (Excel). Step 8 enabled only if `push_uuid_map.json` exists |
| `archimedes_wizard.html` (modified) | New step 8 screen: iframe of HTML report + "Download .xlsx" button |

### Boundaries

- `catalog_report.py` is pure rendering — input is two JSON files, output is two files on disk. No HTTP, no LeanIX calls, no wizard state.
- `push_ldif.py` change is minimal: write one extra file at the end of the existing push loop.
- The wizard endpoints are thin — read files from `output/sessions/<id>/` and serve.

## Data inputs

### `catalog_resolution_report.json` (existing)

Already produced by `pipeline/reference_catalog.py`. Schema (relevant fields):

```json
{
  "entries": [
    {
      "name": "SAP S/4HANA",
      "type": "Application",
      "status": "LINKED",
      "confidence": "VERYHIGH",
      "external_id": "lx_APP_019278",
      "suggested_name": "SAP S/4HANA Cloud",
      "suggested_score": 1.00
    },
    {
      "name": "SAP Ariba",
      "type": "Application",
      "status": "CUSTOM",
      "confidence": "HIGH",
      "external_id": null,
      "suggested_name": "SAP Ariba Buying",
      "suggested_score": 0.82
    }
  ]
}
```

### `push_uuid_map.json` (new)

Written by `push_ldif.py` after a successful `createFactSheet`. Schema:

```json
{
  "workspace": "demo-eu-3",
  "base_url": "https://demo-eu-3.leanix.net",
  "entries": {
    "Application::SAP S/4HANA": {
      "uuid": "abc123-...",
      "created": true
    },
    "Application::Custom legacy ERP": {
      "uuid": "def456-...",
      "created": true
    }
  },
  "failed": [
    {"name": "Broken App", "type": "Application", "error": "..." }
  ]
}
```

Key format: `<Type>::<Name>` — matches the resolver entry's `(type, name)` tuple so the report can join cleanly.

## Report contents

### Header

- Title: `Catalog Linking Review — <client name>`
- Counters: `🟢 N linked auto · 🟡 M to review · 🔴 K custom (no match)`
- Button: `Download .xlsx`

### Table (single, sorted by status: LINKED → REVIEW → CUSTOM)

| Status | Name | Type | Suggested catalog match | externalId | Actions |
|--------|------|------|--------------------------|------------|---------|
| 🟢 LINKED (VERYHIGH) | SAP S/4HANA | Application | SAP S/4HANA Cloud (1.00) | lx_APP_019278 | [Open FS] |
| 🟡 REVIEW (HIGH) | SAP Ariba | Application | SAP Ariba Buying (0.82) | — | [Open FS] [Search catalog] |
| 🟡 REVIEW (MEDIUM) | Fiori | ITComponent | SAP Fiori (0.65) | — | [Open FS] [Search catalog] |
| 🔴 CUSTOM (NONE) | Custom legacy ERP | Application | — | — | [Open FS] |

**Row colors:**
- `LINKED` (any confidence with external_id set) → green
- `REVIEW` (status=CUSTOM but suggested_score ≥ HIGH/MEDIUM threshold) → yellow
- `CUSTOM` (status=CUSTOM, no suggestion or score < threshold) → red

Thresholds for splitting CUSTOM into REVIEW vs final CUSTOM:
- HIGH confidence → REVIEW
- MEDIUM confidence → REVIEW
- LOW or NONE → final CUSTOM

### Action links

For each row, build:

- **Open FS**: `https://<workspace>.leanix.net/<workspace>/factsheet/<Type>/<uuid>` (requires UUID from push_uuid_map)
- **Search catalog**: `https://<workspace>.leanix.net/<workspace>/inventory/referenceCatalog?q=<url-encoded name>` (only for REVIEW rows)

Both `<workspace>` and `<uuid>` come from `push_uuid_map.json`. If the entry has no UUID (push failed for that row), `Open FS` is omitted.

### XLSX export

A single sheet "Catalog Report" with columns: Status, Name, Type, Suggested match, Suggested score, externalId, Open FS URL, Search catalog URL. No formatting — pure data so the user can filter/sort. URLs are clickable hyperlinks in the cells.

## Wizard screen (Step 8)

### When it appears

- Visible only when `output/sessions/<id>/push_uuid_map.json` exists
- Reachable from Step 7 completion ("View catalog linking review" button)
- Reachable from sidebar nav same as other steps

### When `push_uuid_map.json` does not exist

Step 8 shows a placeholder:
> "Run Step 7 (Push) to LeanIX to generate the fact sheet IDs needed for this report.
> [Back to Step 7]"

### When resolver is disabled

If `ARCHIMEDES_USE_CATALOG_RESOLVER` is false or missing, the wizard hides Step 8 entirely from the sidebar (nothing to report).

### Layout

- Iframe loading `/api/session/<id>/catalog-report` (renders the HTML report inline)
- Above iframe: "Download .xlsx" button → triggers `/api/session/<id>/catalog-report.xlsx`

## Endpoints

### `GET /api/session/<id>/catalog-report`
- 200 → `text/html` body, the report
- 404 → if session does not exist OR `push_uuid_map.json` missing

### `GET /api/session/<id>/catalog-report.xlsx`
- 200 → `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` body
- 404 → same as above

## Error handling and edge cases

| Case | Behavior |
|------|----------|
| Session does not exist | 404 |
| Push not yet run for session | Step 8 placeholder "Run Step 7 first" |
| Push ran but `push_uuid_map.json` missing (legacy run before this feature) | Report renders without "Open FS" buttons; "Search catalog" still works for REVIEW rows |
| Push partially failed | Rows for failed entries show status `⚠️ PUSH FAILED`, no "Open FS" link, included in count under CUSTOM if no match, or shown in their resolution status with the warning |
| Resolver disabled | Step 8 hidden from sidebar |
| Resolution report missing | 500 with message "Catalog resolution report not found — was the resolver run?" |
| XLSX generation fails | HTML still shown; toast in UI: "Failed to build .xlsx, see logs"; download endpoint returns 500 |

## Out of scope (explicit)

- Auto-linking HIGH/MEDIUM matches without user confirmation
- Multi-select bulk actions in the report
- Editing fact sheet field values from the report
- Re-running the resolver from the report
- Comparing reports across runs
- Sending the report by email
- Persistence beyond the session folder (no DB, no history page)

## Open questions

None at design time.

## Acceptance criteria

1. After a complete wizard run (Step 4 Generate + Step 7 Push) with the resolver enabled, Step 8 is visible and clicking it shows the HTML report inline.
2. Each row's `Open FS` button opens the corresponding LeanIX fact sheet in a new tab.
3. REVIEW rows have a working `Search catalog` button.
4. Counters in the header match the row counts by status.
5. `Download .xlsx` button produces a valid Excel file with all rows and clickable hyperlinks.
6. Running the wizard without the resolver hides Step 8 entirely.
7. Running the wizard with only Step 4 (no push) shows the placeholder "Run Step 7 first" instead of the report.
8. All tests in the three test files pass.
